# 사실 / 가정 / 미해결 사항

기준: 2026-10-25. 현재 하드웨어 현장 접속을 하지 않았다.

## 확인된 맥락

- BMO는 Raspberry Pi 5 8 GB, 7-inch screen을 사용한다.
- microSD 512 GB와 NVMe SSD 1 TB를 보유한다.
- BMO와 서버는 동시에 실행하지 않는 운영을 원한다.
- 포트폴리오/소개 홈페이지는 GitHub 쪽에서 호스팅하며 동적 웹 테스트 제작은 다른 세션에서 한다.
- 개인 클라우드 파일, GitHub 백업, 다양한 웹 실험을 목표로 한다.
- BMO 화면 R10은 사용자 승인된 기준이지만 실제 Pi 전체 검증 여부는 별개.

## 검증 전 정보

- OS 버전, 커널, 64bit 여부, BMO의 현재 서비스/자동 시작 명령.
- microSD와 SSD의 부팅·마운트 역할, 디스크 상태 및 데이터 중요도.
- Tailscale/SSH/Cloudflare/Docker 현재 설치 상태, 사용 중인 포트.
- 로봇 앱이 종료될 때 카메라, 사운드, RP2040 자원을 정상 해제하는지.
- UPS 배터리의 실제 장시간 전원 공급 능력과 전원 손실 복구.

## 다음 세션 첫 작업

- `scripts/inspect_pi.sh` 읽기 전용 실행.
- 민감 정보 제거 후 점검 결과 검토.
- 실제 BMO 자동 실행/디스크 레이아웃에 맞춘 구체적인 구현 명령 생성.
- BMO 원본 백업 검수 후에만 설치 및 서비스 전환 작업 시작.

## 요구사항 변경 시 기록

서버 서비스의 동시 실행을 허용할 것인지, 서버 모드 기본 부팅 정책, 공개 사이트 도메인, Vault 인증 방식, 디스크 할당량 등은 개발 과정에서 기록한다. 변경에 따라 원본 BMO 구동 회귀 테스트를 반복한다.
