# 기초부터 배우는 BMO 서버 원리

## 1. 하드웨어 vs 운영체제 vs 프로그램

- **Raspberry Pi 5:** 작은 컴퓨터 본체. CPU/RAM/USB/네트워크 등을 제공한다.
- **microSD / NVMe SSD:** 파일을 저장하는 디스크. SD와 SSD 중 **어느 것으로 부팅하는지는 용량만 보고 알 수 없다.**
- **Linux (예: Raspberry Pi OS):** 하드웨어 위에서 프로그램과 파일을 관리하는 운영체제.
- **프로세스(Process):** 실행 중인 프로그램 한 개의 작업 단위. BMO 얼굴/대화 및 웹서버는 서로 다른 프로세스로 관리할 수 있다.
- **서비스(Service):** 백그라운드에서 관리되는 프로그램. `systemd`가 자동 시작·중지·실패 로그를 관리하기도 한다.

비유: Pi는 건물, OS는 건물 관리체계, BMO와 웹서버는 건물 안에서 일하는 서로 다른 팀이다. 서버 모드일 때 로봇 팀이 퇴근하고 서버 팀이 근무하도록 교대한다.

## 2. 왜 Docker를 쓰는가?

Docker **이미지(Image)**는 필요한 소프트웨어를 포장한 실행 설계도, **컨테이너(Container)**는 그 이미지를 실행한 프로세스 묶음이다. **Docker Compose**는 여러 컨테이너의 이미지/포트/볼륨/네트워크 설정을 YAML 파일 한 장으로 관리한다.

- 장점: 앱별 의존성 구분, 설치 및 종료 재현, 데이터 마운트 분리.
- 오해 금지: 컨테이너가 VM처럼 완전한 방화벽이거나 보안 경계라는 뜻은 아니다. 호스트 커널을 공유한다.
- **볼륨/바인드 마운트:** 컨테이너가 종료돼도 데이터를 남기기 위한 파일 연결. 예를 들어 NAS의 파일 폴더를 컨테이너로 전달한다.
- `ports: "127.0.0.1:18080:80"`: 외부 전체가 아닌 Pi 자신의 loopback에서만 접속하도록 포트를 바인딩하는 예시. Docker의 네트워크/방화벽 구성은 추가 검증해야 한다.
- `restart: "no"`: Docker가 종료된 컨테이너를 임의로 다시 시작하지 않게 한다. **이 속성 하나만으로 전체 모드 안전성이 완성되지는 않는다.**

**학습 실습:** 서버용 샘플 컨테이너를 시작하고 `docker compose ps` → 로컬 HTTP 요청 → `docker compose down`을 반복한다. 이 실습은 Docker 설치/환경 확인 이후에 한다.

## 3. 인터넷에 공개되면 무슨 일이 생길까?

- **IP 주소:** 네트워크에서 컴퓨터를 찾아가는 주소.
- **포트:** 컴퓨터에서 어느 앱을 찾는지 구분하는 번호(예: HTTP 80, HTTPS 443, SSH 22).
- **DNS:** `example.com` 같은 도메인 이름을 접속 가능한 대상으로 연결하는 정보.
- **Reverse proxy:** 여러 웹앱 앞에서 요청을 적절한 서버로 전달하는 문지기.
- **Cloudflare Tunnel:** Pi가 Cloudflare 쪽으로 **밖으로 먼저 연결**하고 승인된 웹 요청을 전달받는 구조. 공유기 포트를 무조건 열 필요는 없다. **인증 기능과 동일하지 않다.**
- **Tailscale:** 개인 휴대폰/노트북과 Pi가 사설 네트워크에서 접근하게 하는 수단. 파일 관리/SSH 같은 개인 기능에 이용한다.

실습: Pi 자신에서 `localhost` 접속 → 본인 폰 Tailscale 사설 연결 → 다른 네트워크에서 공개 테스트 사이트 접속. 한 번에 셋을 열지 않고 **단계별로 검증**한다.

## 4. 백업은 복사 이상의 개념

- **미러(Mirror):** 현재 Git 저장소의 참조(브랜치/태그)와 객체를 복사. 지워진 참조까지 동기화할 수 있으므로 과거 보존의 충분조건은 아니다.
- **스냅샷(Snapshot):** 특정 시점의 복원을 위한 버전 기록. restic 같은 도구로 암호화된 백업 보관소를 관리한다.
- **복원(Restore):** 실제로 파일을 재구성하는 행동. 백업 성공 로그만 보고 안심하면 안 된다.
- **3-2-1 원칙:** 최소 3개 사본, 2가지 매체, 그중 1개를 기기 밖에 보관하는 방식의 권장 전략(현실적 여건에 맞춰 단계적으로 확장).

실습: 샘플 텍스트 파일을 만들고 → 백업 → 원본 수정 → 이전 버전 복원. 중요한 BMO 파일로 처음 테스트하지 않는다.

## 5. 1주차 학습 순서 (하루씩 진행할 필요는 없음)

1. `pwd`, `ls -la`, `cd`, `cat`, `df -h`, `free -h`를 사용해 파일 시스템을 관찰한다.
2. `lsblk`, `findmnt`, `mount` **조회만** 하며 SD/SSD 실제 역할을 구별한다.
3. `ps`, `systemctl status`, `journalctl`로 BMO 앱을 누가 시작하는지 찾는다.
4. GitHub `git status`, `git branch`, `git remote -v`로 로컬/원격 저장소 차이를 이해한다.
5. Docker 개념을 익히고 공개되지 않는 예제 1개를 띄운다.
6. Tailscale 개인망만 사용해서 파일 웹 UI를 접속한다.
7. 모드 전환 실패 케이스(프로세스가 안 꺼짐, 디스크 빠짐, 네트워크 끊김)를 설계한다.

## 6. 초보자에게 권하는 사고법

각 명령 전 다음을 확인한다: **① 지금 읽기만 하는가? ② 어떤 파일을 바꾸는가? ③ 되돌릴 수 있는가? ④ 기존 BMO 서비스는 안전한가?**

`sudo`는 높은 권한으로 실행한다는 뜻이다. 이해하지 못한 설치/삭제 명령에 무조건 붙이지 않는다. `rm -rf`, `mkfs`, `dd`, 부트 설정 편집, `curl | sh`는 특히 신중하게 취급한다.
