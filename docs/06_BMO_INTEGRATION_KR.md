# 기존 BMO와의 안전한 통합

## 무엇을 유지하나?

- 기존 원본 프로젝트: https://github.com/GUNOBAE/BGH_BMO
- Pi 5와 7인치 화면, RP2040 PCB, 스피커/마이크/카메라 등 로봇 하드웨어 흐름.
- 사용자가 최종 승인한 R10 화면 파일 및 표정 동작 결과. 새 저장소에는 화면 코드를 복제/재설계하지 않는다.
- Fish Audio 중심의 기존 음성 구동 설계, GPT 대화 경로, 로컬 대체음성 및 현재 개발 브랜치 상태를 덮어쓰지 않는다.
- RP2040/서보 및 IMU 보류 상태 등을 임의로 바꾸지 않는다.

**BMO 전체 통합이 최종 실물 검증 완료되었다고 가정하지 않는다.** 특히 R10 최종 화면 승인과 Pi 실제 적용·음성·하드웨어 검증은 다른 단계다.

## 서버 구현이 BMO에 해서는 안 되는 일

- BMO 코드 자체를 Docker로 강제 이전하거나, OS를 재설치하거나, 화면 창 관리자 구성을 바로 바꾸지 않는다.
- 카메라/마이크/화면/USB RP2040을 서버 컨테이너에 전달하지 않는다.
- 기존 자동실행 유닛을 모르는 상태에서 `disable`, `mask`, `killall`, `systemctl isolate` 등의 광범위 조작을 하지 않는다.
- BMO가 사용 중인 포트/파일/오디오 장치를 미확인 상태로 점유하지 않는다.

## 모드 전환 구현 전에 반드시 알아낼 사실

- 현재 BMO가 어떻게 부팅·실행되는지: systemd(user/system), Wayfire/LXDE autostart, 로그인 스크립트, 수동 프로세스?
- BMO 종료 명령이 안전한지, 종료 후 앱 자식 프로세스가 남지 않는지.
- 얼굴 브라우저/키오스크가 별도 프로세스로 남는지.
- USB/오디오/카메라/서보에서 앱 종료 후 리소스가 해제되는지.
- Tailscale·SSH를 건드리지 않고 원격에서 복구할 수 있는지.

## 회귀 테스트 목록 (ROBOT 재진입 시)

1. 7인치 화면 정상 출력 및 승인된 R10 얼굴 동작 일치 여부.
2. 마이크 음성 입력, GPT 대화, Fish Audio TTS 출력 경로.
3. RP2040 버튼 입력과 양팔 서보가 기존 검증된 범위대로 작동.
4. 카메라, 오디오 장치 점유, 재실행 시 포트 충돌 여부.
5. 서버용 백그라운드 앱/공개 터널이 남지 않았는지.

이 검증은 **현장에서 수행해야 할 체크리스트**이며 통과한 것으로 표시하지 않는다.
